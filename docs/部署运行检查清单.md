> 适用部署方式：项目根目录 `docker compose up -d` 一键启动（JeecgBoot + SQL Server 2022 + Redis）。
>
| 项目 | 值 |
| --- | --- |
| 前端地址 | http://localhost:3665 |
| 后端地址 | http://localhost:8665/jeecg-boot |
| 数据库 | SQL Server，localhost:1433，库名 `temp1218`，用户 `sa`（默认密码 `Supcon1304`） |
| 默认管理员 | `admin / 123456` |
| 启动顺序 | db → db-init（SQL 初始化）→ backend → frontend |

检查时请逐项执行，将“实际结果/是否通过”如实记录；任一步失败时先按文末《故障排查》处理后再继续后续步骤。

## 故障排查

### A. 端口冲突（3665 / 8665 / 1433）

典型现象：

- `docker compose up -d` 报错：`Bind for 0.0.0.0:1433 failed: port is already allocated`；
- 前端打不开、或后端接口 502，但容器状态显示 `Up`/`Restarting`。

排查与处理步骤：

1. **定位占用进程**
   - macOS：`lsof -nP -iTCP:1433 -sTCP:LISTEN`（换 3665/8665 可查其它端口）
   - Linux：`ss -lntp | grep 1433` 或 `netstat -lntp | grep 1433`
   - Windows（PowerShell）：`netstat -ano | findstr :1433`，再用 `tasklist /FI "PID eq <PID>"` 确认进程
2. **释放端口**：停掉占用程序（常见为本机已安装的 SQL Server 服务（`MSSQLSERVER`）、其他项目的 Nginx/Java 进程、或上一次未清理的容器 `docker ps` 中占用端口的旧容器）。停止旧容器：`docker compose down` 或 `docker rm -f <容器名>`。
3. **或改用其他宿主端口**：编辑根目录 `docker-compose.yml` 的 `ports` 映射，例如：
   - `"1434:1433"`（数据库，宿主机连接工具改用 1434）
   - `"8666:8080"`（后端）
   - `"3666:80"`（前端）
   
   注意：改后端宿主端口不影响容器间通信（前端 Nginx 代理的是容器名 `backend:8080`，无需改动）；若改前端端口，还需同步调整后端环境变量 `JEECG_DOMAINURL_PC` 为新地址。
4. **修改后重启验证**：`docker compose up -d`，再执行 `docker compose ps` 确认端口映射生效，重跑本清单第 1～3 节。
5. Docker Desktop / WSL2 环境若仍报端口占用，可重启 Docker 守护进程或执行 `docker compose down --remove-orphans` 清理孤儿容器。

### B. 数据库登录失败

典型现象：

- 后端日志报 `Login failed for user 'sa'`、`Cannot open database "temp1218"`、`Connection refused`；
- `db-init` 容器退出码非 0，日志出现 `Login timeout expired` / `Login failed`；
- 页面登录提示系统异常，验证码接口（依赖 Redis）可能正常但业务接口 500。

排查与处理步骤：

1. **确认数据库已就绪**：SQL Server 启动需要 10～30 秒，初始化太早会连接失败。`docker logs jeecg-sqlserver` 中出现 `SQL Server is now ready for client connections` 后再观察 `db-init` 是否自动重试成功；必要时 `docker compose restart db-init backend`。
2. **核对密码一致性**：`db`、`db-init`、`backend` 三处的 `MSSQL_SA_PASSWORD` 必须相同（默认均为 `Supcon1304`，由同一环境变量注入）。自定义密码时务必在同一命令中传入：
   ```bash
   MSSQL_SA_PASSWORD='YourStrongPassword!' docker compose up -d
   ```
3. **注意 SQL Server 密码策略**：`sa` 密码必须至少 8 位，且包含大写字母、小写字母、数字、特殊字符中的三类，否则数据库以弱密码策略拒绝启动，日志出现 `Password validation failed`。
4. **密码改后不生效（持久化卷）**：SQL Server 的 `sa` 密码在数据卷首次初始化后即固定，事后修改环境变量不会更改已有卷中的密码。两种处理：
   - 继续使用旧密码；或
   - 可丢弃数据时执行 `docker compose down -v` 删除 `mssql-data` 卷后重新 `up -d`（**会清空全部业务数据**）。
5. **手动验证登录**：
   ```bash
   docker exec -it jeecg-sqlserver /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P '你的密码' -C -Q "SELECT 1"
   ```
   - `Login failed for user 'sa'`：密码错误，回到第 2～4 步；
   - `Cannot open database temp1218`：库未创建，说明 `db-init` 未成功，查看 `docker logs jeecg-sqlserver-init`，确认后单独重跑：`docker compose up db-init`（必要时先 `down -v` 全新初始化）；
   - 连接超时/拒绝：容器未就绪或网络问题，检查 `docker compose ps` 与第 4.1 节端口连通性。
6. **核对连接参数**：后端 JDBC URL 为
   `jdbc:sqlserver://db:1433;SelectMethod=cursor;DatabaseName=temp1218;encrypt=false;trustServerCertificate=true`
   容器间必须用服务名 `db`（不是 `localhost`）；宿主机上的连接工具才用 `localhost:1433`。报证书错误时确认 URL 含 `encrypt=false;trustServerCertificate=true`。
7. **查看后端配置来源**：确认 backend 容器环境变量已注入：
   `docker exec jeecg-backend env | grep -i datasource`，用户名/密码/URL 应与编排文件一致；如被旧镜像缓存，`docker compose build --no-cache backend` 后重建。
8. **Redis 异常的区分**：若仅验证码/登录报 Redis 相关错误，执行 `docker logs jeecg-redis` 与 `docker compose restart redis backend`，不要与数据库问题混淆。

### C. 其它常见现象速查

| 现象 | 可能原因 | 快速处理 |
|---|---|---|
| 前端页面白屏、资源 404 | 前端镜像构建异常或浏览器缓存 | `docker compose build --no-cache frontend` 后重建；浏览器强制刷新（Ctrl/Cmd+Shift+R） |
| 接口 502 Bad Gateway | backend 未就绪/已崩溃 | `docker logs jeecg-backend` 查堆栈；常见为数据库连不上，见上文 B |
| 登录页验证码不显示 | Redis 不通或后端未完全启动 | 检查 redis 容器与 2.4 节接口，重启 backend |
| admin 登录提示用户不存在 | 初始化种子数据缺失 | 按 4.4 节核对 `sys_user`；必要时 `down -v` 后重新初始化 |
| 设备档案菜单不显示 | 菜单数据缺失或当前角色未授权 | 管理员在【菜单管理】确认菜单存在，在【角色管理】给角色授权后重新登录；并核对 5.2 节 SQL |
| 普通用户仍能调通写接口 | 后端权限注解/配置缺失 | 检查 Controller 的 `@RequiresPermissions`/权限标识与菜单 `perms` 是否一致，修复后重测 7.3 |

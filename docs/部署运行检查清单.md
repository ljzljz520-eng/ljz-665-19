# 部署运行检查清单

本清单用于部署完成后的运行验证，覆盖后端启动、前端访问、数据库连接、设备档案菜单、增删改查与权限验证六个环节。每一步均给出操作方法与预期结果，末尾附常见故障排查建议。

## 前置条件

- 已执行 `docker compose up -d`，且 `docker ps` 中 `jeecg-sqlserver` / `jeecg-redis` / `jeecg-backend` / `jeecg-frontend` 均为 `Up`，`jeecg-sqlserver-init` 为 `Exited (0)`。
- 默认账号：`admin / 123456`；数据库：`temp1218`；sa 密码默认 `Supcon1304`（如通过 `MSSQL_SA_PASSWORD` 自定义，以实际值为准）。

## 常见故障排查

### 1) 端口冲突（3665 / 8665 / 1433）

**现象**：`docker compose up -d` 报错 `port is already allocated` 或 `bind: address already in use`。

**排查步骤**：

1. 定位占用进程：
   - Linux/macOS：`sudo lsof -i :3665`（或 `:8665`、`:1433`）
   - Windows：`netstat -ano | findstr :3665`，再按 PID 查进程
2. 确认是否为旧容器残留：`docker ps -a | grep jeecg`，若是则 `docker compose down` 后重新启动。
3. 若端口被其他应用占用，二选一处理：
   - 停止占用端口的应用；
   - 修改 `docker-compose.yml` 端口映射（仅改冒号左侧宿主机端口），例如前端改为 `"4665:80"`、后端改为 `"9665:8080"`、数据库改为 `"11433:1433"`，然后 `docker compose up -d` 重建。
4. 改端口后的联动修改：
   - 前端端口变更后，需同步修改 `docker-compose.yml` 中 backend 的 `JEECG_DOMAINURL_PC` 为新的前端地址（如 `http://localhost:4665`），否则登录后跳转/跨域异常。
   - 数据库宿主机端口变更不影响容器间通信（容器内仍走 `db:1433`），仅影响宿主机外部工具连接。

### 2) 数据库登录失败

**现象**：后端日志出现 `Login failed for user 'sa'`，或 `db-init` 初始化容器退出码非 0。

**排查步骤**：

1. 确认密码一致性：`docker-compose.yml` 中 `db`、`db-init`、`backend` 三处均使用 `${MSSQL_SA_PASSWORD:-Supcon1304}`。若启动时通过环境变量自定义了密码，三个服务必须拿到同一个值；检查是否只在某一次 `up` 时传了变量。
2. 检查密码强度：SQL Server 强制强密码策略（至少 8 位，含大小写字母、数字、符号中三类）。弱密码会导致 `db` 容器反复重启，用 `docker logs jeecg-sqlserver` 确认。
3. 注意密码修改不生效的场景：`mssql-data` 卷中已初始化过的实例，sa 密码以首次初始化为准，改环境变量不会重置。如需重置：`docker compose down -v` 清理数据卷后重新启动（**会删除全部业务数据**）。
4. 确认初始化时序：`db-init` 退出码非 0 时，查看 `docker logs jeecg-sqlserver-init` 定位是连接失败还是脚本执行失败；修复后可单独重跑 `docker compose up db-init`。
5. 手工验证连接：`docker exec jeecg-sqlserver /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P '<密码>' -C -Q "SELECT 1"`，返回 `1` 说明数据库本身可登录，问题在后端连接串配置。
